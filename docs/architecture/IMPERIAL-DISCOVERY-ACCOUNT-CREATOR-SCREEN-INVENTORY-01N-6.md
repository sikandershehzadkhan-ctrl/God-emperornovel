## 2. Important implementation distinctions

- `/following` delegates to the shared library renderer with a following mode. Its current renderer fetches library, history, bookmarks and follows; the visible Following state and actual follow-list composition require a focused UX/data-flow check.
- `/for-you` and `/made-for-you` are aliases for the same recommendation renderer. The UI has a personalized-versus-popular fallback message; API-side user isolation still needs verification.
- `/community` is presently a story-discovery hub with navigation links and trending stories. This renderer alone does not establish a discussion forum or chat implementation.
- `/trend-factory` currently references the local trending novels API. This source evidence does not establish chapter-body ingestion or external trend scraping.
- `/omniportal` exposes provider status, federated search and a metadata-import request. It explicitly keeps external reading at the provider and must remain rights-gated server-side.
- Author analytics labels lifetime request counters separately from period metrics and explicitly warns that reader ticket spend is not author income.
- Notification refresh is periodic polling while the page is visible, not push delivery.
